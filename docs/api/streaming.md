# Streaming API Endpoints — Milestone 3

## Overview

The Streaming API provides real-time, server-sent event (SSE) based message generation with support for cancellation, reconnection, and comprehensive error handling.

---

## GET /api/conversations/:conversationId/stream

Subscribe to real-time message generation stream.

### Request

```http
GET /api/conversations/conv-123/stream?messageId=msg-456&workspaceId=ws-789 HTTP/1.1
Authorization: Bearer <JWT_TOKEN>
Accept: text/event-stream
Connection: keep-alive
```

### Query Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `messageId` | string | Yes | ID of the message being generated |
| `workspaceId` | string | Yes | Workspace ID (for authorization) |

### Authorization

- **Authentication**: JWT Bearer token (via Authorization header)
- **Membership**: User must be member of workspace
- **Permission**: `message:read` required

### Response

```http
HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
X-Accel-Buffering: no
```

### Response Events

#### Token Event

Emitted for each token generated by the AI provider.

```
event: token
data: {"token": "hello", "provider": "anthropic", "model": "claude-opus"}

event: token
data: {"token": " world", "provider": "anthropic", "model": "claude-opus"}
```

**Payload**:
```typescript
{
  token: string;        // Single token (may be partial word)
  provider: string;     // Provider ID (anthropic, openai, etc.)
  model: string;        // Model name (claude-opus, gpt-4, etc.)
}
```

#### Usage Event

Emitted at the end with final token counts.

```
event: usage
data: {
  "inputTokens": 150,
  "outputTokens": 80,
  "provider": "anthropic",
  "model": "claude-opus"
}
```

**Payload**:
```typescript
{
  inputTokens: number;      // Total input tokens
  outputTokens: number;     // Total output tokens
  provider: string;         // Provider ID
  model: string;           // Model name
}
```

#### Done Event

Emitted when generation completes successfully.

```
event: done
data: {
  "messageId": "msg-456",
  "inputTokens": 150,
  "outputTokens": 80,
  "model": "claude-opus",
  "provider": "anthropic",
  "completedAt": "2026-07-30T12:34:58.123Z"
}
```

**Payload**:
```typescript
{
  messageId: string;        // Message ID
  inputTokens: number;      // Total input tokens
  outputTokens: number;     // Total output tokens
  model: string;            // Model used
  provider: string;         // Provider used
  completedAt: string;      // ISO 8601 timestamp
}
```

#### Heartbeat Event

Emitted every 30 seconds to keep connection alive.

```
event: heartbeat
data: {"timestamp": "2026-07-30T12:34:56.789Z"}
```

**Payload**:
```typescript
{
  timestamp: string;        // ISO 8601 timestamp
}
```

#### Error Event

Emitted if generation fails.

```
event: error
data: {
  "code": "PROVIDER_ERROR",
  "message": "API request failed",
  "provider": "anthropic"
}
```

**Payload**:
```typescript
{
  code: string;             // Error code (see error codes below)
  message: string;          // Human-readable error message
  provider?: string;        // Provider that failed (if applicable)
  retryable?: boolean;      // Whether client should retry
}
```

### Error Codes

| Code | Status | Meaning | Retryable |
|------|--------|---------|-----------|
| `PROVIDER_NOT_FOUND` | 400 | Provider not registered | No |
| `PROVIDER_NOT_CONFIGURED` | 400 | Provider missing API key | No |
| `PROVIDER_ERROR` | 500 | Provider API error | Yes* |
| `RATE_LIMIT` | 429 | Rate limit exceeded | Yes |
| `TIMEOUT` | 408 | Request timeout | Yes |
| `MESSAGE_NOT_FOUND` | 404 | Message not found | No |
| `CONVERSATION_NOT_FOUND` | 404 | Conversation not found | No |
| `UNAUTHORIZED` | 401 | Missing or invalid auth | No |
| `FORBIDDEN` | 403 | Insufficient permissions | No |

*Some provider errors are retryable (connection resets, timeouts); others are not (invalid API key, invalid model).

### Examples

#### JavaScript/TypeScript Client

```typescript
const messageId = 'msg-123';
const workspaceId = 'ws-456';

const eventSource = new EventSource(
  `/api/conversations/conv-789/stream?messageId=${messageId}&workspaceId=${workspaceId}`
);

let fullText = '';

eventSource.addEventListener('token', (event) => {
  const { token, provider, model } = JSON.parse(event.data);
  fullText += token;
  console.log(`[${provider}/${model}] Token:`, token);
  updateUI(fullText);
});

eventSource.addEventListener('usage', (event) => {
  const { inputTokens, outputTokens } = JSON.parse(event.data);
  console.log(`Usage: ${inputTokens} input, ${outputTokens} output`);
});

eventSource.addEventListener('done', (event) => {
  const { messageId, inputTokens, outputTokens, completedAt } = JSON.parse(event.data);
  console.log('Generation complete at', completedAt);
  eventSource.close();
});

eventSource.addEventListener('error', (event) => {
  const { code, message } = JSON.parse(event.data);
  console.error(`Error: ${code} - ${message}`);
  eventSource.close();
});

eventSource.onerror = () => {
  console.error('Connection lost');
  eventSource.close();
};
```

#### Python Client

```python
import requests
import json

def stream_message(conversation_id, message_id, workspace_id, token):
    url = f'/api/conversations/{conversation_id}/stream'
    params = {'messageId': message_id, 'workspaceId': workspace_id}
    headers = {'Authorization': f'Bearer {token}'}
    
    with requests.get(url, params=params, headers=headers, stream=True) as resp:
        for line in resp.iter_lines():
            if line.startswith(b'event: '):
                event_type = line.decode().split(': ')[1]
            elif line.startswith(b'data: '):
                data = json.loads(line.decode().split(': ')[1])
                if event_type == 'token':
                    print(data['token'], end='', flush=True)
                elif event_type == 'done':
                    print(f"\n\nCompleted: {data['completedAt']}")
                elif event_type == 'error':
                    print(f"Error: {data['code']} - {data['message']}")
```

#### cURL

```bash
curl -i -N \
  -H "Authorization: Bearer eyJhbG..." \
  'http://localhost:3001/api/conversations/conv-123/stream?messageId=msg-456&workspaceId=ws-789'
```

## POST /api/conversations/:conversationId/stream/:jobId/cancel

Cancel an in-flight message generation.

### Request

```http
POST /api/conversations/conv-123/stream/job-456/cancel HTTP/1.1
Authorization: Bearer <JWT_TOKEN>
Content-Type: application/json
```

### Authorization

- **Authentication**: JWT Bearer token (via Authorization header)
- **Membership**: User must be member of workspace
- **Permission**: `message:manage` required

### Response

#### Success (200 OK)

```json
{
  "success": true,
  "jobId": "job-456",
  "status": "CANCELLED"
}
```

#### Error (404 Not Found)

```json
{
  "error": "Job not found"
}
```

#### Error (403 Forbidden)

```json
{
  "error": "Insufficient permissions"
}
```

### Behavior

1. Updates StreamingJob status to `CANCELLED`
2. Publishes cancel signal to Redis channel `job:{jobId}:control`
3. Worker receives signal and aborts generation
4. Partial message persists in database
5. Client receives no further events (connection may close or emit error)

### Examples

#### JavaScript

```typescript
const conversationId = 'conv-123';
const jobId = 'job-456';

const response = await fetch(
  `/api/conversations/${conversationId}/stream/${jobId}/cancel`,
  {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${token}`,
      'Content-Type': 'application/json'
    }
  }
);

if (response.ok) {
  const { success, jobId, status } = await response.json();
  console.log(`Job ${jobId} cancelled (status: ${status})`);
} else {
  console.error('Cancel failed:', response.status);
}
```

#### Python

```python
import requests

def cancel_generation(conversation_id, job_id, token):
    url = f'/api/conversations/{conversation_id}/stream/{job_id}/cancel'
    headers = {'Authorization': f'Bearer {token}'}
    
    resp = requests.post(url, headers=headers)
    if resp.ok:
        print(f"Job {job_id} cancelled")
    else:
        print(f"Cancel failed: {resp.status_code}")
```

## Rate Limiting

Streaming endpoints are subject to rate limiting per workspace:

- **User-level**: 10 concurrent streams per user
- **Workspace-level**: 100 concurrent streams per workspace
- **Provider-level**: Provider-specific limits (Anthropic: 20k RPM, OpenAI: varies by plan)

When rate limit is exceeded:

1. New streaming request returns `429 Too Many Requests`
2. In-flight streams continue unaffected
3. Response includes `Retry-After` header
4. Resume after suggested interval

## Connection Management

### Keepalive

- Heartbeat events emitted every 30 seconds
- Client should expect gaps up to heartbeat interval + network latency
- If no event received for 60 seconds, reconnect

### Reconnection

**Scenario**: Network interruption during stream

**Strategy**:
1. Client detects connection loss (no events for 60+ seconds)
2. Client re-connects: `GET /api/conversations/:id/stream?messageId=...`
3. If generation completed: server returns history from database
4. If generation in-progress: server subscribes to ongoing stream
5. If generation failed: server returns error event

**Important**: Message is immutable once completed. Re-connecting to completed stream returns final message from database.

### Cleanup

When stream completes or connection closes:
1. Redis subscription cleanup (unsubscribe, disconnect)
2. No further events emitted
3. HTTP connection terminated

## Performance Considerations

### Token Emission Rate

- Typical: 50–100 tokens/second (provider-dependent)
- Fastest: 200+ tokens/second (Groq, local models)
- Slowest: 10–20 tokens/second (complex models, high latency)

### Latency

- **Time-to-First-Token (TTFT)**: 500ms–2s (network + provider processing)
- **Token latency**: 10–50ms (depends on provider streaming implementation)
- **Heartbeat latency**: 0–30ms (local Redis Pub/Sub)

### Network Bandwidth

- **Token event**: ~50–200 bytes per event (token size + metadata)
- **Total per message**: 10–100 KB (typical conversation)
- **Concurrent streams**: 100 streams × 1KB/s = 100 KB/s bandwidth

### Resource Usage

- **Memory per stream**: ~1 MB (token buffer + state)
- **Redis Pub/Sub**: Negligible (one channel per job)
- **Database**: 2–3 queries per generation (fetch context, persist message)

## Security

### Token Generation

All requests require valid JWT token in `Authorization: Bearer <token>` header.

Token should include:
- `sub`: User ID
- `iat`: Issued at
- `exp`: Expiration (typically 15 minutes)
- `aud`: Audience (e.g., "synora-api")

### Workspace Scoping

Streaming access is scoped to workspace:
- User must be member of workspace (verified via `requireMembership`)
- Message must belong to conversation in workspace
- Conversation must belong to workspace

### Permission Checks

- **Read stream**: `message:read` permission required
- **Cancel stream**: `message:manage` permission required

Permissions depend on user's role in workspace:
- **Owner**: Full access
- **Admin**: Full access
- **Editor**: Read + manage messages
- **Viewer**: Read-only

### CORS

SSE endpoints follow CORS policy:
- Credentials included in cross-origin requests
- `Access-Control-Allow-Credentials: true`
- `Access-Control-Allow-Methods: GET, OPTIONS`

## Troubleshooting

### Connection Drops Immediately

**Symptom**: `event: error` with code `UNAUTHORIZED`
**Cause**: Invalid or expired JWT token
**Solution**: Refresh token and retry

### Missing Events After 30 Seconds

**Symptom**: No heartbeat or token events received
**Cause**: Network issue or backend crash
**Solution**: Close connection and reconnect

### Slow Token Emission

**Symptom**: 5+ seconds between tokens
**Cause**: Provider overloaded or model complex
**Solution**: None (inherent to provider); user should wait or cancel

### Partial Message Persisted After Cancellation

**Symptom**: Database shows incomplete message
**Cause**: Generation was in-flight when cancel received
**Solution**: This is expected; message can be resumed or edited

### Rate Limit Error (429)

**Symptom**: `event: error` with code `RATE_LIMIT`
**Cause**: Workspace reached concurrent stream limit
**Solution**: Wait for in-flight streams to complete, then retry

## Status Code Reference

| Code | Meaning |
|------|---------|
| 200 | SSE stream established successfully |
| 400 | Invalid request (missing messageId, workspaceId, or provider not found) |
| 401 | Unauthorized (missing or invalid token) |
| 403 | Forbidden (user not workspace member or insufficient permission) |
| 404 | Message or conversation not found |
| 408 | Request timeout (provider didn't respond in time) |
| 429 | Rate limit exceeded (workspace or provider limit) |
| 500 | Internal server error (provider error, database error, etc.) |
| 503 | Service unavailable (provider down) |
